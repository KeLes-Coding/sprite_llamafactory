# 多意图规划器 SFT v3 阶段进展汇报

日期：2026-10-08

## 一、结论摘要

**一句话结论：v3 已验证“重做数据比继续堆训练更有效”，0.6B 模型可作为后续主线；但当前高分主要来自对训练规则和结构的覆盖，换参数、换结构后的泛化能力仍未超过 qwen-flash 锚点，暂不能只凭现有分数判断已经具备稳定上线能力。**

本阶段有四项关键进展：

1. **数据体系完成重建。** 从 v2 的 1,054 个原子扩展到 14,801 个中英文原子，新增 15 类反例和 8 类语言关系算子，形成 76,702 条无重复样本。
2. **数据改造效果明确。** 在训练超参不变的情况下，独立旧题 `challenge_50` 上，0.6B 模型由 54% 提升到 78%，270M 模型由 32% 提升到 60%，提升具有统计显著性。
3. **0.6B 是当前更合适的主模型。** 它在同池改写集上显著优于 270M，格式正确率达到 99%–100%，推理延迟约 150ms，约为 qwen-flash 的五分之一。
4. **泛化仍是主要短板。** 在贴近训练口径的评测上，0.6B 可以领先 qwen-flash；但在参数和结构扰动集上为 89/107，低于 qwen-flash 锚点的 93/107；在独立旧题严格评分上为 38/50，也低于锚点的 42/50。未见城市被替换成深圳、陌生角度被吸附到训练值、多余物理动作等问题仍然存在。

因此，当前阶段的判断不是“模型已经超过大模型”，而是：

- **自有规则学习已经有效，数据路线成立。**
- **0.6B 已具备继续优化的价值，270M 不宜作为主线。**
- **下一阶段应从“扩大同类数据”转向“补覆盖、测泛化、控误执行”。**

## 二、我们已经完成了什么

### 1. 重建数据生产链路

v2 的主要问题不是数据量不足，而是数据虽然有 17.19 万行，实际只由 1,054 个原子反复拼装，并且反例几乎只有“能力问句”一种。模型容易记住固定句式和组合，却没有真正学会复杂语言边界。

v3 围绕这个问题重做了完整链路：

| 环节 | 本阶段完成情况 |
|---|---|
| 原子生成 | 生成 8,471 条中文原子、6,330 条英文原子，共 14,801 条 |
| 反例建设 | 扩展到能力问句、推迟、条件句、愿望、提及、教学、列表外动作等 15 类 |
| 复杂关系 | 新增“只做、改口、撤回、二选一、先后、同时、次数、速度”8 类算子 |
| 多意图拼装 | 覆盖 1–10 个任务，使用模型改写并通过引文校验检查漏项和顺序 |
| 数据质检 | 规则校验、模型盲标和人工复核结合，抽检标签错误率约 1%–3% |
| 最终数据 | 75,702 条训练数据、1,000 条验证数据，全部使用真实工具名 |

与 v2 相比，v3 的核心变化不是简单扩量，而是把“用户一句话到底该执行、回复还是拒绝执行”的边界系统化了。

### 2. 完成两档模型训练

本轮训练保持 v2 超参不变，只替换数据，因此 v2 到 v3 的变化基本可以归因于数据。

| 模型 | 训练耗时 | 分布内 eval loss | 当前判断 |
|---|---:|---:|---|
| Gemma3 270M LoRA | 52 分钟 | 0.0067 | 成本低，但换话术、长句和复杂关系能力不足 |
| Qwen3 0.6B LoRA | 2 小时 26 分钟 | 0.0040 | 综合表现最好，建议作为后续主线 |

两个模型的分布内损失都已经接近饱和。后续继续看 eval loss 意义不大，必须依赖分布外评测判断实际能力。

### 3. 建立多层评测和外部锚点

本轮不再只看训练集同分布验证，而是建立了四层评测：

| 评测集 | 主要用途 | 与训练分布的距离 |
|---|---|---|
| `challenge_v2` | 同一原子换一种说法 | 近 |
| `challenge_v3` | 按现有业务口径手写复杂表达 | 中等，但大部分答案结构训练中见过 |
| `probe_v1` | 单独改变话术、问法、参数或结构 | 较远 |
| `challenge_50` | 独立旧题 | 最远 |

同时引入 qwen-flash 作为锚点，并对线上 schema 差异做了最小机械校正，避免把接口格式差异误判成模型能力差异。

## 三、阶段结果怎么看

### 1. v3 数据改造是有效的

在独立旧题 `challenge_50` 上：

| 模型 | v2 | v3 | 提升 |
|---|---:|---:|---:|
| Gemma3 270M | 32% | 60% | +28 个百分点 |
| Qwen3 0.6B | 54% | 78% | +24 个百分点 |

两个模型的提升均具有统计显著性。由于训练超参未变，可以确认收益主要来自：

- 反例从单一能力问句扩展到 15 类；
- 增加多任务顺序、次数、撤回等关系表达；
- 统一了执行与回复的标注口径；
- 大幅扩充原子说法，降低固定模板依赖。

此外，0.6B 的输出解析成功率从 78% 提升到 100%，270M 从 80% 提升到 96%。这说明格式和基础契约问题已经基本解决，当前矛盾已从“能否正确输出 JSON”转向“是否真正理解用户意图”。

### 2. 0.6B 明显优于 270M

三个 challenge 集上的排序一致，均为 0.6B 优于 270M。尤其在同池改写集 `challenge_v2` 上，0.6B 显著领先；在换话术探针中，0.6B 为 17/19，270M 只有 11/19。

270M 的典型问题是：

- 长句漏任务；
- 简单查询不调用工具；
- 编造不存在的工具或动作；
- 次数和同时执行关系处理不稳。

因此建议后续集中资源优化 0.6B，不再把 270M 作为并行主线。270M 可以保留为低成本实验基线。

### 3. “超过 qwen-flash”只在特定范围内成立

以下采用更严格的参数评分，避免把城市、角度等参数错误算成通过：

| 评测集 | 0.6B | qwen-flash 锚点 | 0.6B 相对表现 |
|---|---:|---:|---|
| `challenge_v2`：同池改写 | 224/241 | 188/241 | +14.9 个百分点，显著领先 |
| `challenge_v3`：自有口径复杂题 | 90/105 | 80/105 | +9.5 个百分点，差异不显著 |
| `probe_v1`：参数和结构扰动 | 89/107 | 93/107 | -3.7 个百分点，差异不显著 |
| `challenge_50`：独立旧题 | 38/50 | 42/50 | -8 个百分点，差异不显著 |

这组结果说明：

- 在训练覆盖充分、规则与自有口径一致时，小模型可以比通用大模型更准；
- 一旦换成训练未覆盖的参数、结构或独立题目，优势就会消失；
- 当前领先主要来自专项训练，而不是通用语言理解能力已经超过 qwen-flash。

这不是负面结果。专项小模型能以约五分之一的延迟达到接近大模型的能力，本身已经证明路线有价值。但汇报和验收时必须说明适用范围，不能用同分布高分代替真实泛化能力。

## 四、目前遇到的主要问题

### 问题 1：参数泛化不足，而且会“静默出错”

训练中的角度只有 11 个取值，城市只有 110 个；深圳占全部天气任务的 49%。因此模型遇到陌生参数时，不一定报错，而是改成自己熟悉的值：

- 200° 被输出成 180°；
- 两圈 720° 被输出成 360°；
- 雷克雅未克、漠河等城市被替换成深圳。

这类错误最危险，因为输出格式完全合法，原来的宽松指标甚至会判为通过。

### 问题 2：复杂结构覆盖仍不完整

模型对常规换问法和换话术已经比较稳定，但以下结构仍然薄弱：

- “各”“都”“再来一遍”“除了”；
- 编号列表；
- “最后做 X，先做 Y”这类倒装顺序；
- “撤回 X，换成 Y”；
- 英文中的次数、同时和先后关系。

这说明当前模型更多是在已有结构内做语义匹配，还没有稳定掌握任务组合规则。

### 问题 3：显式路由会被主题先验覆盖

当用户说“去网上搜逐际动力融资新闻”或“上网查 Luna 售价”时，模型仍倾向使用内部知识库 `rag_query`。原因是训练中只要出现品牌或产品话题，几乎全部标成了内部知识库查询，没有“品牌话题但明确要求上网”的对照样本。

### 问题 4：存在过度执行倾向

0.6B 会把以下内容误当成真实请求：

- 条件句，例如“考满分你就鼓掌”；
- 对别人说的话，例如“小明，你坐下”；
- 不支持的手势，例如敬礼、竖大拇指；
- 场景铺垫中偶然出现的动作词。

它有时还会把不支持的动作替换成相近动作。对于物理机器人，多执行一个动作通常比少执行一个动作风险更高，应把“禁用工具违规率”和“多余物理动作”提升为核心安全指标。

### 问题 5：现有高分评测仍偏向训练分布

`challenge_v2` 和 `challenge_v3` 虽然在字面上与训练句子不同，但 82%–85% 的答案结构在训练集中原样出现过；两套题也都基于我们已经确定的业务口径编写。

因此，它们适合检查“规则有没有学会”，不适合单独证明“新场景也能泛化”。真正拉开差异的是参数和结构扰动集，以及独立旧题。

## 五、对应解法与下一步计划

### 优先级一：先解决高风险的参数错误和过度执行

1. **参数改为槽位化生成。** 在拼装阶段随机替换角度、步数和城市，扩大连续数值与长尾城市覆盖，而不是继续重复固定原子中的少量取值。
2. **降低默认城市偏置。** 大幅降低深圳作为默认值的比例，并增加“未提城市”和“陌生城市”的对照样本。
3. **补充安全反例。** 系统增加条件句、对他人说、场景铺垫、列表外动作和否定范围的最小对。
4. **增加推理侧兜底。** 对物理动作增加二次确认或安全过滤；至少在模型能力稳定前，避免多余动作直接执行。

### 优先级二：补齐结构和路由覆盖

1. 新增“各、都、重复、排除、列表、倒装、撤回后替换”等关系算子。
2. 为英文补齐关系单元，避免当前复杂关系只在中文训练。
3. 增加显式路由最小对：
   - “上网搜 + 品牌/产品”应走 `web_search`；
   - “不要联网，查产品手册”应走 `rag_query`。
4. 为手势和舞蹈补充常见口语别称，同时增加不支持动作的反例，防止模型自行找近似动作。

### 优先级三：升级验收体系

1. **正式评测同时报告主指标和参数严格分。** 城市、角度、步数错误不能再被宽松评分隐藏。
2. **建设独立评测集。** 由不看训练池的人或模型出题，增加英文、真实口语、长尾参数和新结构。
3. **修订历史题。** 单列或修复旧坐标 schema、旧舞蹈别名等遗留题，减少评测噪声。
4. **统一 qwen-flash 契约后重测。** 当前锚点已做机械校正，下一步可使用完全对齐的 schema 和提示词重新推理，形成更稳妥的外部基线。
5. **归档探针与分析脚本。** 将目前位于临时目录的扰动集和严格评分脚本纳入仓库，保证结果可复现。

## 六、建议的阶段决策

### 1. 模型路线

**以 Qwen3 0.6B LoRA 为主线，暂停对 270M 的同等资源投入。**

理由是 0.6B 在准确率、复杂指令和语言泛化上均更稳，约 150ms 的推理延迟仍明显优于 qwen-flash；270M 可保留用于快速验证数据改动，但不作为最终能力目标。

### 2. 数据路线

**继续采用“原子池 + 关系算子 + 最小对反例”的路线，但下一版不再追求总行数，重点提升参数、结构和安全边界的覆盖。**

本轮已经证明，76,702 条高针对性数据优于 171,900 条高复用数据。下一阶段应看覆盖质量，而不是样本总量。

### 3. 验收口径

**暂不把同池改写集的高分作为上线结论。** 下一阶段至少同时满足以下三类验证：

- 自有业务规则集保持稳定；
- 独立评测集上不明显落后于 qwen-flash 锚点；
- 参数严格分和多余物理动作指标达到可接受水平。

### 4. 当前阶段定位

当前已经完成了从“验证能否训练”到“验证数据路线有效”的跨越。下一阶段的核心任务，是把专项记忆能力转化为对长尾参数、新结构和安全边界的稳定泛化能力。
