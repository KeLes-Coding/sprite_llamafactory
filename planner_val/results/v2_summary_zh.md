# 多意图规划器 SFT 阶段总结：v1 → v2

日期：2026-10-06

## 0. 版本定义

| 版本 | 定位 | 数据 | 模型与训练 |
|---|---|---|---|
| **v1** | 跑通流程 | 旧版数据（train+val 共 18,832 条），单一工具协议、固定工具顺序 | gemma3-270m 全量 SFT |
| **v2（当前）** | 在 v1 基础上加入 Hammer 式工具名替换 | v3.3.0 数据：训练集 171,900 行。每条 instruction 出现 5 次（1 次真实工具名 + 4 次随机别名）；工具 schema 增加了枚举含义描述 | gemma3-270m LoRA；Qwen3-0.6B LoRA |

v2 的 Hammer 改造：把工具名替换成随机别名，迫使模型根据 description 选择工具，而不是死记工具名。

## 1. 结果总表

主指标为基准兼容准确率：工具、顺序、参数都正确，且没有多余或禁用调用。

|---|---|---|---|---|
| v1 | gemma3-270m | 全量 SFT | 98.75%（旧验证集 1,839 条） | 20%（10/50） |
| v2 | gemma3-270m | LoRA r32 | 98.75%（val2k） | 32%（16/50） |
| v2 | **Qwen3-0.6B** | LoRA r32 | **98.90%**（val2k） | **54%（27/50）** |

## 2. 结论

1. **v2 相对 v1 有改善，但提升不能确认。**
   - gemma 从 20% 升到 32%，提升主要集中在 unseen_value（0 → 5），而 ambiguity_distractor 反而从 6 降到 2。
   - 配对检验不显著。而且 v1 → v2 同时改了数据、schema 描述和训练方式（全量改为 LoRA），无法把提升归因于 Hammer。
2. **换底座的收益明确。** 数据相同，Qwen3-0.6B 比 gemma3-270m 高 22 个百分点，且显著。说明 270M 的容量和预训练先验是瓶颈之一。
3. **微调同时有收益和副作用。**
   - Qwen 原始模型在 val2k 上只有 2.85%，微调后达到 98.90%，输出协议和 schema 遵循完全靠微调学会。
   - 但原始模型做对、微调后反而做错的有 8 题：坐标题 010/012/017/036，否定或只提及题 037/038/040/048。微调把底座原本「坐标不是指令」「被否定的内容不执行」的判断覆盖掉了。
4. **分布内验证集已没有区分度。** gemma 和 Qwen 在 val2k 上都约 98.8%，但 challenge 相差 22 个百分点。
5. **距离可用还很远。** 最好的 v2 模型只有 54%，比 qwen-flash 的 90% 低 36 个百分点，禁用工具违规率仍有 16%。

## 3. 问题汇总

### 3.1 数据问题（主因）

| 编号 | 问题 | 证据 |
|---|---|---|
| D1 | **「每个分句对应一个任务」的捷径。** 42.1% 的样本是 7 个及以上任务的长串拼接，1 个任务的样本只占 5.6% | 失败归因中「过度拆分、收尾话术被做成工具」最多：gemma 11 题，Qwen 6 题 |
| D2 | **反例只有一种形态。** 反例占 52%，但几乎都是「能力询问 → reply」 | 否定约束、只提及不执行、纠正类题目大量失败 |
| D3 | **关键语言现象覆盖为 0。** 收尾话术「再说一句 X」、否定约束「不要 X，只 Y」、提及不执行、纠正「不是 X 是 Y」、数字或坐标干扰 | 对应题目在两个 LoRA 模型上基本全错；坐标题 5 道两者都 0 分 |
| D4 | **web_search 与 rag_query 的区分样本不足** | 「上网搜」被路由到 `rag_query`：gemma 5 题，Qwen 4 题，换底座也没改善 |
| D5 | **别名重复稀释了语义多样性。** 171,900 行里不同的 instruction 只有 34,380 条 | 相同算力下，实际见到的不同说法只有 1/5 |

### 3.2 Hammer 改造本身的问题

| 编号 | 问题 | 说明 |
|---|---|---|
| H1 | **效果未被单独验证** | 没有「v2 去掉别名」的对照组；challenge 只用真实工具名，测不到别名带来的泛化 |
| H2 | **分布内看不出差异** | 别名与真实工具名的准确率几乎相同（98.6% vs 98.9%）。只能说明模型学会了读别名，不能说明它更理解 schema |
| H3 | **unseen_value 的改善可能另有来源** | v2 同时给 schema 加了枚举含义描述，0 → 5 的提升更可能来自这一项 |
| H4 | **没有引入 Hammer 的另一半** | Hammer 原文还构造了「删除正确工具 → 空调用」的无关性样本。v2 的反例只有能力询问一种，没有对应形态 |

### 3.3 模型与训练

| 编号 | 问题 | 说明 |
|---|---|---|
| M1 | 270M 容量不足 | 同数据下 Qwen3-0.6B 显著更好；后续建议以 0.6B 为主 |
| M2 | 微调覆盖了底座先验 | 原始 Qwen 能做对的坐标题和否定题，微调后做错 |
| M3 | 输出格式不稳定 | Qwen LoRA 在 challenge 上 parser_valid 只有 0.78：有编造的枚举值，也有 2 题 JSON 格式损坏（嵌套重复字段、引号未转义） |
| M4 | 实验存在混杂 | Qwen 用 bs128 / lr 2e-4，gemma 用 bs32 / lr 1e-4；v1 → v2 同时改了数据和训练方式 |

### 3.4 评测问题

| 编号 | 问题 | 说明 |
|---|---|---|
| E1 | val2k 与训练集同分布 | 88% 的 semantic_id 与训练集重合，只能用来检查是否学会了训练分布 |
| E2 | challenge 样本太少 | 50 题时 1 题就是 2 个百分点，95% 置信区间约 ±14 个百分点 |
| E3 | 坐标题口径 | 5 道坐标题按 v3.2.0 带坐标的 schema 编写，v3.3.0 的 schema 已去掉经纬度。去掉这 5 题后结论不变 |
| E4 | 缺少别名或工具变化的分布外探针 | 无法评估 Hammer 的本来目标，即工具名或 schema 变化后的泛化 |

### 3.5 安全问题

| 编号 | 问题 | 说明 |
|---|---|---|
| S1 | 额外的物理动作 | Qwen LoRA 的禁用工具违规率为 16%，例如「不要移动，只查电量」时先执行了 `stand_up`。物理动作类的误执行风险需要推理侧兜底 |

## 4. v3 建议方向（按优先级）

| 优先级 | 事项 | 对应问题 |
|---|---|---|
| P0 | 数据加入「语言算子」维度（否定、只做、提及、纠正、收尾话术、干扰信息），用最小对比对构造反例 | D1–D3、M2 |
| P0 | challenge 扩充到 200 题以上并封存；新增别名或工具变化的分布外探针 | E2–E4、H1 |
| P1 | 重新配比任务长度：1–3 个任务的样本占约 60%；别名倍数从 4 降到 1–2 | D1、D5 |
| P1 | 补充 web 与 rag 的显式区分样本，以及 Hammer 式「缺少正确工具 → 回复」样本 | D4、H4 |
| P1 | 做消融：去掉别名、统一超参，单独评估 Hammer 和超参的影响 | H1、H3、M4 |
| P2 | 推理侧兜底：受约束解码保证 JSON 和枚举合法，被否定的工具在后处理中剔除 | M3、S1 |
